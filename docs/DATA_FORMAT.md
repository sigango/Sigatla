# Data format

Sigatla keeps everything a reader needs in plain JSON files, so notes can be written by Claude,
reviewed in a diff, and edited by hand.

```
my-atlas/
  atlas.json            project settings (title, language, sources)
  sources/              the PDFs you added (papers, lecture slides)
  build/<source-id>/    extracted pages, figures and slide images (regenerated by `sigatla extract`), reading
                        packs and contact sheets (regenerated by `sigatla pack`)
  notes/<source-id>.json  notes for one source (written by `sigatla read` or by an AI assistant)
  notes/<source-id>.part-<k>.json  more notes for a long source read in parts (only `nodes`)
  notes/_shared.json    the axis, shared concepts and links across sources (written by `sigatla connect`)
  notes/_qa.json        saved questions and answers (written by the local server)
  site/                 the built website (written by `sigatla build`)
  AGENTS.md, CLAUDE.md  a short guide for AI assistants (written by `sigatla init` or `sigatla guide`)
```

## `atlas.json`

```json
{
  "title": "XAI reading list",
  "subtitle": "XAI papers I am reading",
  "language": "en",
  "model": "claude-opus-5-5",
  "sources": [
    {"id": "gradcam", "kind": "paper", "file": "sources/gradcam.pdf", "label": "Grad-CAM · ICCV 2017", "short": "Grad-CAM"},
    {"id": "cv2-l03", "kind": "slides", "file": "sources/cv2-lecture-03.pdf", "label": "CV2 · Lecture 3"}
  ]
}
```

- `language`: language of the notes and of the interface (`en` or `vi`; other values write notes in that
  language and fall back to English for the interface).
- `kind`: `paper`, `slides` (lecture slides; each slide is kept as an image) or `notes` (any other PDF).
- `id`: lowercase letters, digits and `-`; it prefixes every node id of that source.
- `short` (optional): a short name for the jump bar at the top right of the map (`sigatla add --short`). Without it the
  bar shows the label, cut to fit.

## `notes/<source-id>.json`

The full form (every field, the sections of each note type, the relations) is in [NOTES_FORM.md](NOTES_FORM.md).

```json
{
  "source": {
    "id": "gradcam", "kind": "paper", "label": "Grad-CAM · ICCV 2017",
    "title": "Grad-CAM: Visual Explanations from Deep Networks via Gradient-based Localization",
    "authors": "Selvaraju et al.", "year": "2017",
    "summary": "Markdown body of the source's hub node"
  },
  "nodes": [
    {
      "id": "gradcam.weights",
      "type": "formula",
      "title": "Channel weights from pooled gradients",
      "short": "One sentence shown in tooltips and lists.",
      "body": "Markdown with $inline$ and $$display$$ math. Figures: ![Figure 2](fig:gradcam/fig-2)",
      "questions": ["Why average the gradients spatially?"],
      "figures": ["gradcam/fig-2"],
      "pages": [3, 4],
      "links": [{"to": "gradcam.heatmap", "rel": "uses", "note": "Why the link holds, one or two sentences."}]
    }
  ]
}
```

Node `type`:

| type | used for |
| --- | --- |
| `concept` | an idea, definition or problem |
| `method` | a method, algorithm or architecture |
| `formula` | an equation, with every symbol explained |
| `design` | an experimental or study design choice, with the reason for it |
| `result` | a finding, with the numbers as reported |
| `limitation` | a limitation, threat to validity or open question |
| `data` | a dataset or benchmark |
| `example` | a worked example (mostly from slides) |
| `related` | another work the source builds on or argues with (id prefix `rw.`) |

Relation `rel` (read as "source REL target"): `part_of`, `uses`, `extends`, `motivates`, `contrasts`,
`measures`, `tests`, `limits`, `supports`, `refutes`, `cites`, `frames`, `complements`.

Ids: `<source-id>.<slug>` for a source's own nodes, `rw.<slug>` for related work (shared across sources, so two
papers citing Grad-CAM point at the same `rw.gradcam`), `shared.<slug>` for concepts that span sources.

Text written as interpretation rather than taken from the source starts with **Interpretation:**
(**Diễn giải:** in Vietnamese).

## `notes/_shared.json`

```json
{
  "axis": {"title": "...", "short": "...", "body": "..."},
  "nodes": [ { "id": "shared.faithfulness", "type": "concept", "...": "..." } ],
  "links": [ {"from": "gradcam.heatmap", "to": "shared.faithfulness", "rel": "measures", "note": "..."} ]
}
```

## `build/<source-id>/manifest.json`

Written by `sigatla extract`.

```json
{
  "id": "gradcam", "kind": "paper", "pages": 12,
  "page_text": ["text of page 1", "..."],
  "figures": [
    {"id": "gradcam/fig-2", "file": "figures/fig-2.png", "page": 3, "kind": "figure",
     "caption": "Figure 2: ...", "w": 1200, "h": 640}
  ]
}
```

Figure ids are `<source-id>/<name>`. For slides every page is rendered as `slide-<page>`; build-up steps
(a slide exported several times as it fills in) have `"kind": "step"` and are listed in `frames`:

```json
"frames": [
  {"slide": 28, "pages": [27, 28], "title": "Value Iteration", "section": "Finite Horizon Optimal Control",
   "subsection": "Value Iteration with a For-Loop", "video": false, "links": [], "text": "slide text"}
]
```

`build/<id>/slides.md` has the same information as readable text, one section per slide.

For slides, `sigatla pack` adds `visuals`: for every page, why its image is worth looking at (`formula`,
`picture`, `drawing`), or `[]` when its extracted text says everything. Graphics repeated on many pages (logos,
header bars) are ignored as template.

```json
"visuals": {"1": [], "2": ["drawing"], "3": ["formula", "picture"]}
```

The pack draws the slides that need an image onto contact sheets, `build/<id>/sheets/<part>-<n>.jpg` (`deck-<n>`
for a deck read in one go, `part-<k>-<n>` for a part): up to four slides per image, 784 px wide each, labeled with
the PDF slide number.

## The data injected into the page

`sigatla build` merges everything into one object, injected into `site/index.html` as
`<script type="application/json" id="atlas-data">`:

```json
{
  "meta": {"title": "...", "subtitle": "...", "lang": "en", "generated": "2026-11-16T10:00:00Z"},
  "groups": [
    {"id": "gradcam", "label": "Grad-CAM · ICCV 2017", "short": "Grad-CAM", "kind": "paper", "planet": "gas",
     "color": {"night": "#f2b35b", "paper": "#c27612", "contrast": "#ffbf4d"}},
    {"id": "shared", "label": "Shared concepts", "kind": "shared", "color": {}},
    {"id": "related", "label": "Related work", "kind": "related", "color": {}}
  ],
  "nodes": [
    {"id": "axis", "type": "axis", "group": "shared", "title": "...", "short": "...", "body": "...", "questions": []},
    {"id": "gradcam", "type": "hub", "group": "gradcam", "title": "...", "short": "...", "body": "...", "questions": [],
     "figures": [], "pages": []}
  ],
  "links": [ {"source": "gradcam.weights", "target": "gradcam.heatmap", "rel": "uses", "note": "..."} ],
  "figures": {
    "gradcam/fig-2": {"src": "assets/gradcam/fig-2.png", "caption": "Figure 2: ...", "page": 3, "kind": "figure", "w": 1200, "h": 640}
  }
}
```

- Each source becomes a `hub` node (a planet) whose id is the source id; every node of the source links to it.
- `axis` (the sun) is optional; without `notes/_shared.json` the build writes a plain one from `atlas.json`.
- `groups[].color` may be empty for `shared` and `related`; the page has built-in colors for those two.
